1. Overview of Website Features

The personal portfolio website is a multi-page static web application engineered to showcase my civil and construction engineering technology coursework, technical internships, and mechanical design projects. Built strictly adhering to vanilla web standards without external libraries or frameworks, the site comprises five unified pages:

  • Home Page (index.html): Engaging hero introduction, quick highlight cards detailing my internship experiences at Langan Engineering & Environmental Services and The LiRo Group (Middlesex County infrastructure), project previews, and navigation calls-to-action.
  • About Me (about.html): Complete personal background, academic curriculum at NJIT (BIM modeling, structural steel, concrete, surveying, estimating), chronological industry timeline, verified credentials (NJIT Civic Engagement and Cisco CCNA badges), and personal interests in robotics and trail exploration.
  • Projects (projects.html): Comprehensive showcase of 3 technical projects: two-story Revit modern residential BIM modeling (CET 317 Final), embedded Arduino digital calculator with 3D-printed enclosure, and standardized Lego minifigure assembly drafting (Section A-A cross section). Features category filtering and an accessible modal dialog.
  • Skills (skills.html): Categorized matrix covering Civil Design & BIM Software, Programming & Embedded Hardware, Municipal Infrastructure/QA Inspections, and Technical Leadership with visual proficiency meters (role="progressbar").
  • Contact (contact.html): Direct professional correspondence channels and a validated client-side inquiry form that dynamically launches an email to hrp73@njit.edu.
  • Design System & Accessibility: Single external stylesheet (style.css) using CSS custom properties for seamless Light/Dark theme switching, responsive media queries (375px mobile to 1440px desktop), and universal WCAG AAA contrast ratios.
  • JavaScript Interactivity (script.js): Accessible responsive hamburger navigation menu with aria-expanded and focus management, universal keyboard accessibility (skip-link transfer to <main tabindex="-1">, focus trapping, Arrow key filter navigation, modal restoration), theme toggle with localStorage persistence, and client-side contact form validation.

2. Challenges Faced & Solutions

Challenge 1: Responsive Layout Without CSS Frameworks

Problem: Without frameworks like Bootstrap or Tailwind, building multi-column layouts across phone (375px) and laptop (1440px) screens often leads to horizontal overflow.
Solution: Developed a pure CSS Grid and Flexbox system with clamp() and minmax() functions. Media queries at 768px and 480px collapse multi-column cards into single-column vertical stacks with fluid percentage widths, bounded by global overflow-x: hidden.

Challenge 2: WCAG AAA Color Contrast in Dual Themes

Problem: Light and dark modes have contrasting luminance requirements; accent blues frequently fail contrast checks against dark surfaces.
Solution: Mapped brand colors to #0369a1 (5.2:1 against white) in light mode and #38bdf8 (7.8:1 against #1e293b) in dark mode. Body text maintains >14:1 contrast in both modes, surpassing WCAG AAA.

Challenge 3: Keyboard Navigability & Focus Management

Problem: Modal dialogs and mobile menus can trap keyboard focus or lose focus when closed.
Solution: Implemented explicit programmatic focus management in script.js. Opening the modal shifts focus to the first interactive item; closing it restores focus to the invoking trigger (previousActiveElement.focus()). All elements have 3px high-contrast :focus-visible rings.

3. Example of Codex Making a Mistake & How It Was Fixed

The Mistake: During initial implementation of script.js, Codex attached the contact form submit listener directly inside DOMContentLoaded without checking if the form existed: 

// Codex's initial unshielded code:
const contactForm = document.getElementById('contact-form');
contactForm.addEventListener('submit', (e) => {
  e.preventDefault();
  // validation logic...
});

The Issue: Because script.js is shared across all five pages, on index.html, about.html, projects.html, and skills.html, #contact-form evaluated to null. The browser console immediately threw an unhandled TypeError: Cannot read properties of null (reading 'addEventListener'), halting execution and breaking the hamburger menu on those four pages.

The Fix: Testing with Chrome DevTools console caught this error. I instructed Codex to implement defensive guards across all DOM initializers: 

// Remediated code with defensive guard:
const initContactFormValidation = () => {
  const contactForm = document.getElementById('contact-form');
  if (!contactForm) return; // Defensive guard: safely exits on non-contact pages

  contactForm.addEventListener('submit', (e) => {
    e.preventDefault();
    // validation logic...
  });
};

Verification: Reloading all five pages verified 0 console errors and full interactivity across all views.
